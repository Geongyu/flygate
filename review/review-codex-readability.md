# 검토 의견 — Codex · 가독성

검토일: 2026-09-27
검토 범위: 루트 및 ui README, 두 HTML 소스, 실제 브라우저의 시판 전 화면과 PV 보고 평가·시그널 벤치마크 탭. 의학적 판정 기준과 원본 수치의 정확성 전체를 검증한 문서는 아니다.

사용자 우선 요구: 디자인은 가독성이 좋아야 한다. 클로드와 공동 작업 예정.

## 우선 수정할 것

1. **고정 폭으로 오른쪽 내용이 잘린다.** 두 HTML의 최상위 컨테이너가 1440px 고정이다(각 파일 48행). 1280px 브라우저에서 오른쪽 패널·버튼·안내 일부가 보이지 않는다. 화면 폭에 맞춰 컨테이너를 줄이고, 좁은 화면에서는 3열을 2열/1열로 재배치한다. 표가 넓을 때는 표 영역에만 가로 스크롤을 둔다. 화면 전체를 축소해 작은 글씨를 더 작게 만드는 방법은 피한다.
2. **작은 라벨이 많다.** 표 머리글과 보조 라벨이 11px, 출처·도구명이 12px인 곳이 많다. 본문 15–16px, 표 머리글과 중요한 설명 13–14px를 작업 기준으로 권한다. 한국어 라벨의 넓은 자간(.13em)도 줄인다. 숫자에는 고정폭 글꼴을 유지해도 좋다.
3. **핵심 목적을 첫 화면에 명시해야 한다.** 현재 첫 제목은 `PARP1 × Niraparib`이고 PV는 `시판 후 이상사례 평가`다. 제목 바로 아래에 `신약 탐색부터 약물감시까지, 근거를 넘어선 주장을 걸러냅니다` 같은 목적 문장을 추가한다. 그 아래에서 `주장 → 근거 확인 → 통과 / 반려 / 전문가 검토` 예시 하나를 먼저 읽게 한다.
4. **세로 공간 배분을 조정한다.** 고정 높이가 시판 전 1830px, PV 1700px다. PV 벤치마크 탭에서 탭 아래 큰 공백이 관찰되며, 보고 평가에서는 뇌 시각화와 긴 패널 때문에 인과성 평가가 아래로 밀린다. 콘텐츠에 따라 높이가 늘어나도록 하고 주요 판정·근거를 위로 올린다. 커넥톰은 보조 설명으로 축소한다.
5. **흐린 비선택 카드도 읽을 수 있어야 한다.** PV 판단 경로의 비선택 단계는 카드 전체 opacity가 낮아 글자까지 어둡다. 선택 상태는 테두리·배경으로 구분하고 설명 글자는 충분히 밝게 유지한다.

## 문구와 정보의 위계

- `크리틱 3단` → `3단계 주장 검증`을 주표기로 사용하고 기존 용어는 보조 설명에 둔다.
- `트리아지` → `보고 우선 분류`, `정상 오탐` → `정상 주장 오반려`처럼 무엇을 했는지 드러낸다.
- `PASS / REJECT / HUMAN`은 `통과 / 반려 / 전문가 검토`로 통일하거나 한국어를 병기한다.
- `System 1 / System 2`보다 `빠른 분류 / 근거 검토`를 먼저 보여주고 구현 명칭은 작게 병기한다.
- 시판 전 헤더는 FDDD, PV 헤더는 FLYGATE다. 제품 이름을 통일하되 필수 템플릿·데이터 크레딧은 푸터에 그대로 보존한다.
- Naranjo 문항은 번호와 점수만으로 이해하기 어렵다. 펼쳐보기에서 문항·답변·근거·미확인 여부를 읽을 수 있게 한다. 의학적 점수 산정의 타당성은 별도 검토 대상이다.

## 예시와 실제 실행 결과를 구분할 것

- README는 Jev 미연결을 명시하고 PV 헤더는 `트리아지 확률은 예시 값`이라 안내한다. 하지만 이 안내는 오른쪽에 있어 현재 화면에서 잘리고, 본문은 `Jev 즉시 판정`, `아낀 LLM 호출 3 / 6`처럼 실행 결과 형태로 표시된다. 큐와 해당 지표 바로 옆에 `미연결 · 예시 시뮬레이션`을 항상 표시해야 한다.
- `사람이 볼 건수 -74%`는 실제 업무 감소를 측정한 것처럼 읽힌다. 현재 README가 사람의 분류 정확도 검증이 없다고 밝힌 만큼 `자동 필터 후 남은 항목 14 / 54`와 `필터 제외율 74% · 전문가 검증 전`을 같은 카드에 표시하는 편이 정확하다. 제외된 항목도 다시 볼 수 있게 유지한다.
- README의 `화면의 모든 숫자 ... 지어낸 값이 없다`는 포괄 문구는 트리아지 예시 확률과 구분되도록 범위를 한정해야 한다.
- README의 분류상 검토 대상 19건과 최종 표시 14건 사이에 추가 필터가 있다면 조건과 제외 5건의 이유를 명시한다. 서로 다른 집계라는 설명이 없으면 숫자 불일치처럼 보인다.

## 클로드와 함께 작업할 때 참고할 기준

- 이번에는 검토 파일만 추가했다. 기존 HTML·데이터·README는 수정하지 않았다.
- 구현 담당자는 먼저 폭·높이·글자 크기·정보 순서를 고치고, 그 다음 색상과 장식을 다듬는 것을 권한다.
- UI 변경과 수치·의학적 판정 변경은 각각 근거를 남겨 검토할 수 있게 한다. 데이터가 없으면 `미조회`, `—`를 유지한다.
- 완료 확인: 1280px 및 1440px 화면, 125% 확대에서 주요 판정과 예시 안내가 잘리지 않는지 확인한다. 두 PV 탭과 후보 선택 후에도 확인한다.

## 확인이 더 필요한 것

- WHO-UMC/Naranjo 판정, PRR/ROR 기준의 도메인 정확성은 이번 가독성 검토에서 승인하지 않았다.
- 대조비 수치 측정과 키보드·스크린리더 전체 접근성 검사는 아직 하지 않았다.
- 수치 원본과 HTML 내 상수의 전수 대조는 별도 작업이다.
