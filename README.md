한국 에이전틱 AI 해커톤 제출물. 화면 두 개와 그 뒤의 실행 결과를 검토받으려고 정리했다.
**이 문서를 읽고 `review/` 폴더에 검토 의견을 남겨 달라.**

작성 2026-09-27. 담당 이건규. 팀 저장소는 `kakyungkim/korea-agentic-hackathon-2026`.

## 1. 무엇을 만들었나

시판 전 탐색부터 시판 후 감시까지, 한 후보(니라파립)를 끝까지 따라가면서
**단계마다 그 분야의 전통 기준으로 채점하고, 근거를 넘어선 주장은 반려하는** 에이전트다.

핵심은 결과를 더 많이 내는 게 아니라 **결과가 말해도 되는 범위를 정하는 것**이다.
크리틱 3단이 그 일을 한다.

```
[1] 근거 ID가 붙었나  →  [2] 숫자가 원본 로그와 맞나  →  [3] 추론이 근거를 넘지 않았나
     (모델 안 씀)              (모델 안 씀)                    (LLM)
```

1단과 2단을 통과해도, 즉 숫자가 다 맞아도 3단에서 반려될 수 있다.
예: "PARP1 -10.178, Factor Xa -7.967이므로 PARP1 선택적이다" — 두 숫자 모두 실측이지만
다른 단백질의 도킹 점수는 교차 비교할 수 없으므로 반려.

## 3. 실행한 것과 나온 수치

원본은 `data/measurements.json`, `data/jev_triage.json`, `data/jev_queue.json`.
화면의 **통계·모델 수치는 전부 여기서 왔다**. 아직 측정 안 한 자리는 화면에 `미조회`, `—` 로 비워 두었다.

다만 화면 2의 보고 큐 6건 중 **3건만 실제 FAERS 보고**이고 나머지 3건은 합성 예시다.
각 행에 `실제 보고` / `합성 예시` 배지로 구분해 두었다. 이 6건에 붙은 Jev 확률은
합성 예시에 대해서도 실제로 모델을 호출해 받은 값이지, 손으로 적은 값이 아니다.

### NVIDIA NIM (health.api.nvidia.com, 계정 키로 실제 호출)

| NIM | 결과 |
|---|---|
| MSA-Search | PARP1 상동 서열 101개 (Uniref30_2302), 63.6초 |
| OpenFold3 | pLDDT 95.95, pTM 0.828, ipTM 0.658 · 4R6E 결정 구조 대비 CA RMSD **1.0 Å**, 리간드 1.16 Å |
| DiffDock | 8조합. 재도킹 RMSD 니라파립@PARP1 **0.71 Å**, 아픽사반@Xa 0.56 Å, 셀레콕시브@COX-2 0.55 Å |
| Boltz-2 | 8조합 + PARP1 벤치마크 39종 친화도 예측 |
| OpenFold2 | **실패.** HTTP 500 `CUDA error: an illegal memory access`. 6회 시도, 입력 바꿔도 동일. 서버측 장애 |
| NemoGuard topic-control | **실패.** HTTP 500 TensorRT-LLM CUDA 오류. 대체로 `nemotron-3.5-content-safety`는 정상 |

OpenFold2가 안 되고 우리는 단백질+리간드 복합체를 다루므로 OpenFold3로 갔다.
NVIDIA 공식 스킬 `bionemo-msa-structure-prediction-pipeline`이 MSA-Search → OpenFold3 조합을 규격으로 제시한다.

### 친화도 예측 벤치마크 (신약 쪽 전통 기준)

ChEMBL에서 PARP1 IC50 활성 4,180건 → 고유 화합물 3,370종 → 활성 범위가 고루 퍼지도록 39종 선택.
Boltz-2로 전부 예측하고 ChEMBL pChEMBL 중앙값과 대조.

| 지표 | 값 |
|---|---|
| Spearman | 0.767 |
| Pearson | 0.746 |
| MAE | 0.71 log 단위 |
| Enrichment (상위 25%) | 2.41 (9개 중 5개) |
| 민감도 / 특이도 (pIC50 ≥ 7) | 0.80 / 0.86 |
| 포즈 RMSD ≤ 2 Å 성공률 | 3 / 3 (재도킹 대조) |

### FAERS 시그널 탐지 벤치마크 (PV 쪽 전통 기준)

openFDA 전체 20,692,690건. 약물 10종 × 보고 상위 8사건 = 80쌍.
PRR, ROR + 95% CI, χ²(Yates). 신호 기준은 EMA/MHRA의 **PRR ≥ 2, χ² ≥ 4, n ≥ 3**.
정답지는 해당 약물 FDA 라벨의 이상반응·경고 절에 그 용어가 있는지.

- 80쌍 → 통계 신호 **54건**
- 라벨 대조 민감도 0.72, 정밀도 0.57 (철자 정규화 후)
- Nemotron으로 54건을 분류: 용어 불일치 19, 검토 대상 19, 적응증 10, 질병 진행 4, 약효 지표 2
- 여기에 **Jev 1.13.0**을 앞단으로 붙여 54건을 다시 통과시켰다 (총 204.5s, 건당 3.79s, 28,002 토큰)
- Jev가 `보고 서식 잡음` 확률 0.7 이상으로 짚어낸 5건은 **Nemotron 범주로는 표현이 안 되던 것**이다:
  METHOTREXATE–OFF LABEL USE 0.93, NIRAPARIB–OFF LABEL USE 0.92, CLOZAPINE–HOSPITALISATION 0.81,
  CELECOXIB–DRUG INEFFECTIVE 0.73, METHOTREXATE–DRUG INEFFECTIVE 0.72
- 이 5건을 빼면 검토 대상은 **9건. 자동 필터 제외율 83%** (전문가 검증 전)

2단 구조를 임계값별로 대조한 실측 (자동 = Jev 결론 채택, 이관 = Nemotron 호출):

| 임계값 | 자동 | 이관 | LLM 호출 절감 | Nemotron 일치 | 잡음 검출 |
|---|---|---|---|---|---|
| 0.90 / 0.10 | 26 | 28 | 48% | 23 / 26 | 2 |
| 0.85 / 0.15 | 31 | 23 | 57% | 28 / 31 | 2 |
| **0.80 / 0.20** | **38** | **16** | **70%** | **34 / 38** | **3** |
| 0.70 / 0.30 | 48 | 6 | 89% | 39 / 48 | 5 |

Jev 지연은 문항 수·입력 길이와 무관하게 3.3–3.7s로 고정이다. 따라서 이득은 **응답 속도가 아니라
호출 수와 비용**이고, 한 호출에 문항 4개를 묶는 것이 공짜다.

PRR 상위권이 전부 가짜라는 게 핵심이다.
클로자핀–조현병 PRR 105는 적응증이고, 와파린–INR 상승 PRR 94는 약이 의도한 작용의 검사 수치다.

### 크리틱 3단 성능

평가 8건(과잉해석 4, 정상 4). 전부 위 실측 수치 기반.

| 모델 | 과잉해석 적발 | 정상 통과 | 소요 |
|---|---|---|---|
| `nemotron-3-super-120b-a12b` | 4 / 4 | 3 / 4 | 41.8초 |
| `nemotron-3.5-lightning-30b-a3b` | 0 / 4 | 1 / 4 | 294.5초 |

Lightning의 0점은 성능이 아니라 출력 토큰 문제다. 추론형이라 생각에 토큰을 다 쓰고
`VERDICT:` 줄 전에 잘렸다. 재평가가 필요하다.

## 4. 검토받고 싶은 것

우선순위 순이다. **전부 다 볼 필요는 없고, 틀린 것과 빠진 것만 짚어 주면 된다.**

### 4-1. 수치 해석이 과하지 않은가 (가장 중요)

우리가 만든 게 "과잉해석을 잡는 도구"인데, **우리 자신의 주장이 과잉해석이면 치명적이다.**
아래 주장들을 같은 잣대로 검사해 달라.

1. "DiffDock 재도킹 RMSD 0.71 Å로 결정 구조를 재현했다" — 공결정 구조에 원래 리간드를 다시
   넣은 것이다. 이걸 "도킹 설정이 작동한다"는 근거로 쓰는 게 정당한가? 어디까지 말할 수 있나?
2. "OpenFold3가 4R6E를 CA RMSD 1.0 Å로 맞혔다" — 4R6E는 공개 구조라 학습 데이터에 있을 수
   있다. 이 수치를 제시하는 것 자체가 오해를 부르지 않나?
3. "Boltz-2 Spearman 0.767" — n=39, PARP1 한 타깃이다. 어느 선까지 주장 가능한가?
4. "자동 필터 제외율 83%" — 분류 정확도를 사람이 검증하지 않았다. 이 표현이 정당한가?
   화면에서는 `사람이 볼 건수 감소` 대신 `자동 필터 제외율 · 전문가 검증 전`으로 바꿨는데 충분한가?
6. Jev와 Nemotron이 어긋난 4건(0.80/0.20 기준)에 대해 어느 쪽이 맞는지 아직 안 가렸다.
   이 상태로 "70% 절감"을 제시하는 게 정당한가, 아니면 불일치 해소가 선행되어야 하나?
5. Naranjo 점수를 10문항 중 4문항이 비어 있는 채로 계산했다. 이 점수를 제시하는 게 맞나,
   아니면 "산출 불가"로 처리해야 하나?

### 4-2. PV 도메인 정확성

- WHO-UMC 등급명과 판정 근거가 맞는가 (화면 2 하단 인과성 패널)
- Naranjo 10문항 배점과 구간(≥9 확실 / 5–8 개연성 높음 / 1–4 가능함 / ≤0 의심스러움)이 맞는가
- 신호 기준 PRR ≥ 2, χ² ≥ 4, n ≥ 3 이 현재 통용되는 기준인가. ROR 하한 > 1 을 병기해야 하나
- 라벨을 정답지로 쓰는 방식의 한계. SIDER 같은 대안이 나은가

### 4-3. 남은 구멍

이미 알고 있는 것들이다. 더 있으면 알려 달라.

- ~~검토 14건에 보고 서식 용어가 섞여 있다~~ → Jev로 5건 걸러냈다 (`보고 서식 잡음` 범주 추가).
  다만 `APIXABAN–FALL`은 확률 0.7에 못 미쳐 아직 검토 목록에 남아 있다.
- 라벨 매칭이 문자열 비교다. 철자 정규화(ANAEMIA→ANEMIA)까지만 했고 동의어는 못 잡는다.
- PubMed 문헌 근거를 아직 안 붙였다.
- Jev와 Nemotron의 불일치 4건을 아직 안 가렸다. 어느 쪽이 오류인지 판정이 필요하다.
- Jev 확률의 보정(calibration)을 안 봤다. 0.8이라는 임계값은 지금 임의로 고른 것이다.
- 크리틱 평가 8건은 표본이 너무 작다.

## 5. 검토 의견 남기는 곳

`review/` 폴더에 `review-<이름>.md` 로 새 파일을 만들어 달라.
**기존 파일은 고치지 말 것.** 형식은 자유지만 아래가 있으면 좋다.

```markdown
# 검토 의견 — <이름>

## 틀린 것
- (항목) 무엇이 왜 틀렸는지, 맞는 값이나 표현

## 빠진 것
- (항목)

## 과잉해석으로 보이는 주장
- (주장) 어디까지만 말할 수 있는지

## 그 외
```

근거가 있으면 출처를 적어 달라. 확실하지 않으면 "확실하지 않음"이라고 적어 주는 게
그냥 넘어가는 것보다 낫다.
